# Internacionalización (i18n)

Transforma el proyecto a soporte bilingüe con `react-i18next`, o audita el estado actual de los textos.

## Argumentos

`$ARGUMENTS` puede ser:

- `audit` — solo escanea y reporta textos hardcodeados sin hacer cambios
- `setup` — instala y configura la infraestructura i18n sin tocar componentes
- vacío — flujo completo: auditoría → confirmación → setup → transformación

## Modo audit (`/i18n audit`)

### 1. Escanear componentes

Busca textos hardcodeados en todos los archivos `.tsx` y `.ts` bajo `src/`:

```bash
grep -rn --include="*.tsx" --include="*.ts" \
  -E '>[A-ZÁÉÍÓÚÑáéíóúñ][^<{]+<|placeholder="|title="|label="|aria-label="|alt="' \
  src/ | grep -v "//\|className\|import\|console\|\.test\.\|\.spec\."
```

Complementar con:

```bash
grep -rn --include="*.tsx" \
  -E '"[A-ZÁÉÍÓÚÑáéíóúñ][^"]{3,}"' \
  src/ | grep -v "className\|import\|console\|\/\/"
```

### 2. Verificar si i18n ya está configurado

```bash
cat package.json | grep -E "i18next|react-i18next"
ls src/i18n/ 2>/dev/null && echo "i18n configurado" || echo "i18n NO configurado"
```

### 3. Generar reporte

Mostrar al usuario:

- Resumen: N archivos con textos hardcodeados, M strings detectados
- Lista por archivo con número de línea y el texto encontrado
- Estado: si i18n ya está configurado o no
- Recomendación: qué pasos faltan

Ejemplo de formato del reporte:

```
## Auditoría i18n

Estado: i18n NO configurado

Archivos con textos hardcodeados: 4
Strings detectados: 12

### src/features/auth/pages/Auth.tsx
  - L23: "Iniciar sesión"
  - L45: "Correo electrónico"
  - L52: "Contraseña"
  - L61: "Entrar"

### src/shared/components/layout/DashboardLayout.tsx
  - L18: "Panel principal"
  ...
```

Detener aquí si el modo es `audit`. No hacer ningún cambio.

## Modo setup (`/i18n setup`)

Solo configura la infraestructura. No toca componentes existentes.

### 1. Instalar dependencias

```bash
npm install i18next react-i18next i18next-browser-languagedetector
```

### 2. Crear estructura de directorios

```
src/
└── i18n/
    ├── index.ts          ← configuración de i18next
    └── locales/
        ├── es.json       ← español (idioma base del proyecto)
        └── en.json       ← inglés
```

### 3. Crear `src/i18n/index.ts`

```typescript
import i18n from 'i18next'
import LanguageDetector from 'i18next-browser-languagedetector'
import { initReactI18next } from 'react-i18next'

import es from './locales/es.json'
import en from './locales/en.json'

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: {
      es: { translation: es },
      en: { translation: en },
    },
    fallbackLng: 'es',
    interpolation: { escapeValue: false },
    detection: {
      order: ['localStorage', 'navigator'],
      caches: ['localStorage'],
    },
  })

export default i18n
```

### 4. Crear `src/i18n/locales/es.json` y `src/i18n/locales/en.json`

Crear los archivos vacíos con objeto `{}`. Los keys se poblarán durante la transformación.

```json
{}
```

### 5. Importar en `src/main.tsx`

Agregar al inicio del archivo, antes de cualquier import de componentes:

```typescript
import './i18n'
```

### 6. Crear componente `LanguageSwitcher`

Crear `src/shared/components/ui/LanguageSwitcher.tsx`:

```tsx
import { useTranslation } from 'react-i18next'
import { Button } from '@/components/ui/button'

export const LanguageSwitcher = () => {
  const { i18n } = useTranslation()
  const isEs = i18n.language?.startsWith('es')

  return (
    <Button variant="ghost" size="sm" onClick={() => i18n.changeLanguage(isEs ? 'en' : 'es')}>
      {isEs ? 'EN' : 'ES'}
    </Button>
  )
}
```

Exportar desde `src/shared/index.ts` si existe.

## Modo completo (`/i18n`)

### 1. Ejecutar auditoría

Realizar todos los pasos del modo `audit` primero.

Si no se detectan textos hardcodeados → informar al usuario y detener. El proyecto ya está listo o no tiene texto visible.

### 2. Confirmar con el usuario

Mostrar el reporte y preguntar:

> "Se detectaron N strings en M archivos. ¿Procedemos con la transformación completa?
> Esto instalará react-i18next y modificará los componentes listados.
> Responde sí/no."

Si responde no → detener.

### 3. Ejecutar setup

Realizar todos los pasos del modo `setup`.

### 4. Transformar componentes

Para **cada archivo** del reporte de auditoría:

#### 4a. Agregar import de `useTranslation`

```tsx
import { useTranslation } from 'react-i18next'
```

#### 4b. Agregar el hook al componente

Dentro del componente (o en el nivel más alto si es un componente de página):

```tsx
const { t } = useTranslation()
```

Si el componente ya importa otros hooks de react, agregar en la misma zona.

#### 4c. Reemplazar strings por claves de traducción

Estrategia de naming para las claves:

- Usar la ruta del archivo como prefijo para evitar colisiones: `auth.login.title`, `dashboard.welcome`, `common.save`, etc.
- `common.*` → textos que se repiten en múltiples lugares (botones, labels genéricos)
- `<feature>.<página>.<descripción>` → textos específicos de una sección

Ejemplos de transformación:

```tsx
// Antes
<h1>Iniciar sesión</h1>
<Button>Guardar</Button>
<Input placeholder="Correo electrónico" />

// Después
<h1>{t('auth.login.title')}</h1>
<Button>{t('common.save')}</Button>
<Input placeholder={t('auth.login.emailPlaceholder')} />
```

Para atributos que no son children JSX, usar `t()` directamente:

```tsx
// aria-label, placeholder, title, alt
<img alt={t('dashboard.logoAlt')} />
```

#### 4d. Poblar los archivos de traducción

Tras transformar todos los componentes, agregar todas las claves detectadas a `es.json` con el texto original en español, y a `en.json` con la traducción al inglés.

Formato estructurado por sección:

```json
// es.json
{
  "common": {
    "save": "Guardar",
    "cancel": "Cancelar",
    "loading": "Cargando..."
  },
  "auth": {
    "login": {
      "title": "Iniciar sesión",
      "emailPlaceholder": "Correo electrónico",
      "passwordPlaceholder": "Contraseña",
      "submitButton": "Entrar"
    }
  }
}
```

```json
// en.json
{
  "common": {
    "save": "Save",
    "cancel": "Cancel",
    "loading": "Loading..."
  },
  "auth": {
    "login": {
      "title": "Sign in",
      "emailPlaceholder": "Email address",
      "passwordPlaceholder": "Password",
      "submitButton": "Sign in"
    }
  }
}
```

### 5. Verificar compilación

```bash
npm run build
```

Si falla, mostrar el error y corregir antes de continuar. Los errores más comunes son:

- Import de `i18n` faltante en `main.tsx`
- Tipo incorrecto en `t()` — asegurar que los argumentos son strings literales

### 6. Resumen final

Mostrar al usuario:

- Dependencias instaladas
- Archivos de infraestructura creados
- Componentes modificados (N archivos, M strings reemplazados)
- Claves generadas en `es.json` / `en.json`
- Cómo usar el `LanguageSwitcher` en el layout
- Próximos pasos: revisar traducciones al inglés, agregar más idiomas si se necesita
